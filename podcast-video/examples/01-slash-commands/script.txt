A: 大家好，欢迎收听《Claude Code 怎么用》播客，我是小林。
B: 大家好，我是老周。
A: 老周，今天这期我们聊 Claude How To 教程的第一章：斜杠命令，也就是 Slash Commands。很多人刚打开 Claude Code，看到一个斜杠就懵了，这到底是个啥？
B: 我先打个生活里的比方。你去楼下那家常去的早餐店，老板一看见你就问："老样子？"你点个头，一碗豆浆两根油条就上来了。你不用每次从头说"我要一碗甜豆浆、不要太烫、油条要脆一点"。
A: 对，熟客的暗号。
B: 斜杠命令就是你和 Claude 之间的"老样子"。在输入框里打一个斜杠，后面跟一个名字，比如斜杠 clear，它就知道你要干什么，不用你写一大段话去描述。
A: 那这些"暗号"都是从哪来的？
B: 教程里分了四类。第一类是内置命令，Claude Code 自己带的，比如斜杠 help、斜杠 clear、斜杠 model。第二类是技能，也就是 Skills，是你自己写的，放在一个叫 SKILL 点 md 的文件里。第三类是插件命令，是你装的插件带进来的。第四类是 MCP 提示词，是外部服务器提供的命令。
A: 能不能再用生活场景对应一下？
B: 可以。就像你的手机：内置命令是手机出厂自带的相机、计算器；技能是你自己设置的快捷指令，比如"回家模式"一键开空调关蓝牙；插件命令是你从应用商店下载的 App；MCP 提示词呢，就像手机里的银行小程序，真正干活的是银行那边的服务器，手机只是个窗口。
A: 这个好懂。那我们先从内置命令说起吧。教程里说有六十多个，我看得眼花。
B: 不用全背。你在输入框里打一个斜杠，就会弹出完整列表；再多打几个字母，它会帮你过滤。就像你在通讯录里输入"张"，所有姓张的都出来了。
A: 有一个小细节我觉得挺贴心。新版本里，如果你把命令打错了，按回车它会直接报错，而不是悄悄帮你执行一个"长得最像的"命令。
B: 这个改动很重要。你想啊，你跟出租车师傅说去"人民路"，他没听清，自作主张把你拉到"人民北路"，那不就麻烦了？宁可他问一句"您说的是哪儿"，也比自作聪明强。
A: 哈哈，确实。那挑几个最常用的给大家讲讲？
B: 第一组，管理对话内容的：斜杠 clear 和斜杠 compact。clear 是清空对话，重新开始，它还有两个别名，斜杠 reset 和斜杠 new。compact 是压缩对话，把前面聊过的内容浓缩成一份摘要，还可以告诉它重点保留什么。
A: 这俩有什么区别？
B: 打个比方。你在白板上开了一下午的会，白板写满了。clear 就是拿板擦全擦掉，换个新话题。compact 呢，是先让同事拍张照、整理成一页会议纪要贴在旁边，再擦白板，接着往下讨论。
A: 那我什么时候该用哪个？
B: 换了一个完全不相关的任务，用 clear；任务还没做完，但对话太长了，用 compact。配合斜杠 context 一起看，它会用一个彩色格子图告诉你，上下文已经用了多少。
A: 就像手机看存储空间还剩多少。
B: 没错。第二组，我叫它"后悔药和平行宇宙"：斜杠 rewind、斜杠 branch、斜杠 fork。
A: 后悔药是 rewind？
B: 对，rewind 可以把对话，甚至代码，倒回到之前的某个时间点。它的别名也很直白，叫斜杠 undo，还有斜杠 checkpoint。就像玩游戏时的存档点，打 Boss 失败了，读档重来。
A: 那 branch 和 fork 呢？
B: branch 是在当前这个点"分叉"，你进入一个对话副本继续试，原来的对话还保留着，想回去用斜杠 resume 就行。好比你写论文，不确定新思路好不好，先"另存为"一份草稿去改，原稿不动。
A: fork 又不一样？
B: fork 是把当前对话复制一份，放到后台变成一个独立的会话，你自己留在这边继续干活。它俩从此各走各的。就像你把一份方案复印一份交给同事，说"你按这个方向研究一下"，你自己接着做手上的事。
A: 我还看到一个斜杠 subtask。
B: subtask 是派一个"分身"去完成一个子任务，它继承了全部对话，做完以后把结果带回来给你。区别在于：fork 出去的同事，做完了是他自己的；subtask 派出去的跑腿小哥，办完事会回来跟你汇报。
A: 这个区分很形象。我自己最喜欢的一个是斜杠 btw。
B: btw，by the way，顺便问一下。
A: 对。Claude 正在忙主任务的时候，你可以用它问一个旁支问题，而且这个问答不会污染主对话的上下文。
B: 这就像开会的时候，你给旁边同事递一张小纸条："这个缩写是啥意思？"同事写个答案递回来，会议照常进行，会议记录里也不会多出这一段。
A: 还有一个斜杠 goal，我觉得挺有意思。
B: goal 是给整个会话定一个完成条件。比如"把支付服务从 REST 迁移到 gRPC，并且集成测试全部通过"。Claude 会朝着这个目标一轮一轮干下去，状态栏里还会显示用了多少时间、多少轮、多少 token。做完了用斜杠 goal clear 取消。
A: 这就像装修的时候跟师傅说清楚：不是"你今天干八小时"，而是"厨房能做饭、卫生间不漏水，才算完工"。
B: 太对了。验收标准比工时更重要。而且如果后台任务卡住超过三十分钟没进展，它会主动跟你汇报情况，而不是闷头一直耗着。
A: 像一个靠谱的师傅，遇到问题会打个电话问你。
B: 再说一个小而美的：斜杠 cd。它可以切换工作目录，而且不会破坏提示词缓存。以前切目录，缓存就"凉了"，下一轮会更慢、更贵。
A: 这个怎么类比？
B: 你在一个办公室工作很久了，同事都熟，资料都在手边。以前换一个工位，就像换了一家公司，什么都得重新熟悉。现在用 cd，就像只是把椅子挪到隔壁桌，你脑子里的东西都还在。
A: 剩下还有好多，比如斜杠 model 换模型，斜杠 effort 调思考力度，斜杠 usage 看用量，斜杠 init 初始化 CLAUDE 点 md。
B: 对。这里提醒一下大家，教程里也列了已经废弃的命令，比如斜杠 vim 已经移除了，要去斜杠 config 里设置编辑模式；斜杠 agents 也不再是一个能用的向导了，想管理子代理，直接跟 Claude 说就行。
A: 就像小区换了物业，原来的报修电话停用了，贴了个告示告诉你新的办法。
B: 对，所以不要照着旧教程硬敲。
A: 好，内置命令聊得差不多了。接下来是重头戏：自定义命令。
B: 这里有一个关键变化：自定义斜杠命令，已经合并进了技能，也就是 Skills。
A: 什么意思？
B: 以前你在点 claude 斜杠 commands 目录下放一个 md 文件，就多了一个命令。现在推荐的做法是，在点 claude 斜杠 skills 下面建一个文件夹，里面放一个 SKILL 点 md。老办法依然能用，不会坏。
A: 那如果两边同名了呢？
B: 技能优先。比如你同时有 commands 下的 review 点 md，和 skills 下的 review 文件夹，最后用的是技能那个。
A: 就像你手机里同一个人存了两个号码，系统优先拨你标了"主号码"的那个。
B: 对。那为什么要搬到技能呢？教程里列了五个好处。我用做菜来解释。
A: 好，我爱听做菜的。
B: 老式的命令，就像一张菜谱卡片，上面只有文字步骤。技能呢，是一个完整的"料理包"。第一，它是个文件夹，可以放脚本、模板、参考资料，就像料理包里有调料包、说明书、量勺。第二，自动触发，Claude 觉得用得上的时候会自己调用，就像一个懂事的徒弟，看你在切葱，就知道要准备炒锅了。第三，可以控制谁能调用，是只能你叫，还是 Claude 也能自己用。第四，可以用 context 设成 fork，在一个隔离的子代理里运行，就像让徒弟去另一个灶台做，不弄乱你的台面。第五，渐进式加载，用到哪个资料才打开哪个，不会一上来把整本书摊满桌子。
A: 那创建一个技能具体要怎么做？
B: 很简单。建一个目录，比如 my-command，里面写 SKILL 点 md。文件开头是一段叫 frontmatter 的配置，用三个短横线包起来，写上 name 和 description；下面就是给 Claude 的操作步骤，第一步、第二步、第三步。
A: description 是不是特别重要？
B: 非常重要。它决定了 Claude 什么时候会想到用这个技能。就像你给家里的抽屉贴标签，写"杂物"，等于没写；写"电池、充电线、螺丝刀"，谁都知道找东西去哪开。
A: frontmatter 里还有哪些字段？
B: 挑几个关键的。argument-hint，提示用户该传什么参数。allowed-tools，规定这个命令不用问你就能用哪些工具。model，指定用哪个模型。还有两个开关：disable-model-invocation 设成 true，就只有用户能调用，Claude 不能自己触发；user-invocable 设成 false，就不会出现在斜杠菜单里。
A: allowed-tools 怎么理解？
B: 就像你请了钟点工，给她一把只能开厨房和客厅的钥匙，书房和卧室的门她打不开。比如 commit 命令只允许用 Bash 里的 git 命令，它就不会去乱跑别的东西。
A: 那 disable-model-invocation 呢？
B: 这个用在有副作用的操作上，比如部署到生产环境。好比家里的燃气总阀，只有大人能去开，小孩子再聪明也不让他自己拧。部署这种事，必须你亲手按按钮。
A: 安全感拉满。接下来是参数。
B: 参数有两种写法。第一种是美元符号 ARGUMENTS，代表你在命令后面敲的全部内容。比如有个 fix-issue 命令，内容写"修复第 ARGUMENTS 号 issue"，你输入斜杠 fix-issue 123，它就变成"修复第 123 号 issue"。
A: 像填空题。
B: 对，或者像奶茶店的点单模板："一杯，大中小杯，几分糖，冰量"。你说"大杯、三分糖、少冰"，店员就填进去了。第二种写法是美元符号 0、美元符号 1，按位置取参数。比如斜杠 review-pr 456 high，0 号是 456，1 号是 high。
A: 就像寄快递，第一格填收件人，第二格填电话，位置不能乱。
B: 没错。还有一个变量，CLAUDE_PROJECT_DIR，会被替换成项目根目录的绝对路径。
A: 接下来这个我觉得是最强大的：动态上下文。
B: 对。在技能里写一个感叹号，加上反引号包起来的 shell 命令，比如感叹号 git status。在把提示词发给 Claude 之前，这些命令会先执行，结果直接填进去。
A: 举个例子？
B: 教程里的 commit 命令就是这样写的：先自动获取当前 git 状态、git diff、当前分支、最近五条提交记录，然后才让 Claude 去写提交。
A: 这让我想到去医院看病。你还没进诊室，护士已经帮你量好了体温、血压，填在单子上。医生一看单子，马上就能进入状态，不用从"你哪里不舒服"开始问。
B: 这个比方特别准。最佳实践里有一条就是：不要假设 Claude 知道当前的状态。你要用感叹号把现场情况"量"出来给它。
A: 还有一个艾特符号？
B: 对，用艾特加文件路径，就可以把文件内容引用进来。比如"审查一下艾特 src 下的 helpers 点 js"。就像你在群里艾特一个人，他马上就被拉进对话里了。只不过这里拉进来的是文件。
A: 好，那插件命令和 MCP 命令我们快速过一下。
B: 插件命令的格式是：斜杠，插件名，冒号，命令名。比如 frontend-design 冒号 frontend-design。如果没有重名，也可以直接写命令名。
A: 为什么要加前缀？
B: 就像一个班里有三个"小明"，老师就得说"一组的小明""二组的小明"。没有重名的时候，直接喊名字就行。
A: MCP 呢？
B: MCP 的格式是：斜杠 mcp，两个下划线，服务器名，两个下划线，提示词名。比如 mcp 双下划线 github 双下划线 list_prs，列出 GitHub 上的 PR。还可以带参数，比如 jira 创建 issue，后面跟标题和优先级。
A: 权限这块也有讲究吧？
B: 对。在权限设置里，写 mcp 双下划线 github，就是允许整个 GitHub 服务器；后面加通配符星号，是允许它所有工具；写到具体工具名，就只允许那一个。新版本还收紧了规则：一条规则只匹配它名字写的那台服务器，不会误伤名字长得像的。
A: 好比门禁卡，有的能进整栋楼，有的只能进某一层，有的只能开某一间会议室，而且三号楼的卡刷不开三十三号楼。
B: 哈哈，对。
A: 那一个斜杠命令敲下去之后，背后到底发生了什么？
B: 教程里有一张流程图。你输入斜杠 optimize，Claude Code 先去 skills 和 commands 目录里找文件，找到 SKILL 点 md；然后解析 frontmatter；接着执行那些感叹号命令，拿到输出；再把 ARGUMENTS 替换成你的参数；最后把组装好的完整提示词交给 Claude 处理，返回结果。
A: 听起来像去餐厅点了一个套餐：服务员拿到你的单子，后厨先找菜谱，看看有什么特殊要求，备好料，按你说的"少辣"调整，再下锅、上菜。
B: 完全一致。
A: 教程这个文件夹里还附了八个现成的命令示例，可以直接拿来用？
B: 对。斜杠 optimize，分析性能问题和内存泄漏。斜杠 pr，准备 Pull Request 的检查清单。斜杠 generate-api-docs，生成 API 文档。斜杠 commit，带上下文的提交。斜杠 push-all，暂存、提交、推送一条龙。斜杠 doc-refactor，重组文档。斜杠 setup-ci-cd，配置 pre-commit 钩子和 GitHub Actions。斜杠 unit-test-expand，扩充单元测试覆盖率。
A: push-all 我特别想说一下，它带安全检查。
B: 对。推送之前，它会检查有没有把密钥文件提交进去，比如点 env、点 key、点 pem、credentials 点 json；会区分真的 API Key 和占位符；会拦截超过 10 MB 又没用 Git LFS 的大文件；还会检查 node_modules、dist 这种构建产物。
A: 这就像出门前那句口诀："身手钥钱"：身份证、手机、钥匙、钱包。推送代码前也要摸一摸口袋。
B: 哈哈，我回头也要背一下。安装方法也很简单：推荐的是把每个 md 文件复制到 skills 下对应的文件夹里，改名成 SKILL 点 md；也可以按老办法直接复制到 commands 目录。放在项目目录下，团队都能用；放在家目录的点 claude 下，就是你个人专用。
A: 一个是办公室的公共冰箱，一个是你自己抽屉里的零食。
B: 对，最后我们说说最佳实践。
A: 我来念"要做的"，你来补"别做的"？
B: 好。
A: 第一，命名清晰、动作导向。
B: 别为一次性的事情建命令。你不会为了一次聚会专门刻一枚印章。
A: 第二，写好 description，包含触发条件。
B: 别在命令里塞复杂逻辑。复杂的放到脚本文件里，技能的文件夹就是干这个用的。

B: 先检查文件放的位置对不对，是不是在 skills 下的文件夹里叫 SKILL 点 md，或者在 commands 下；再看 frontmatter 里的 name 对不对；可以用斜杠 reload-skills 重新扫描，或者重启会话；最后用斜杠 help 看看有哪些命令。
